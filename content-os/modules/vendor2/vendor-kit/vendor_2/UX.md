# User experience acceptance

One administration workspace (not the live store redesign). Vietnamese interface, desktop 1440x900 and mobile
390x844 screenshots and browser flows. Keyboard focus, labeled inputs, readable contrast, error states and no clipped content.

1. Overview: active objectives, jobs, budget, draft count, blockers, last sync; mock/live labels always visible.
2. Planning/calendar: topic clusters, existing-page suggestions, priorities, proposed date, owner and status.
   Data comes from Vendor 1. A user can move date or amend a brief with revision checking.
3. Brief detail: audience, intent, target questions, outline, evidence needs, product scope and SEO source date.
4. Article editor: content with per-block sources, unresolved gaps, revision history, SEO title/description and preview.
5. Review/publication: compare exact revision, approve/reject, destination, staging/live warning, schedule/cancel,
   result receipt and UNKNOWN state with reconciliation action.
6. Run/data history: error reasons, finite retries, cost, snapshot/code/prompt IDs; no raw secrets or signed URLs.

The first demonstration must show a user editing a brief, generating a draft from fixtures, inspecting a source,
changing the draft (old approval becomes invalid), approving a new revision and creating one MOCK draft.
No screen needs to expose all internal job rows. Keep drill-down available without making the user operate workers.
