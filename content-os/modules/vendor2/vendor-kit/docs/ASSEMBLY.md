# Eight finite assembly checks: not a fresh full-system audit

Use the exact accepted image/commit digests. If code or configuration changes, rerun the affected contract/security paths.
No new architecture is introduced during assembly. A baseline with mocks is not an accepted live connector.

A1 Verify service versions/contract hashes, TLS, identity and project isolation, role mapping, limits and disabled live flags.
A2 Run one scoped SEO provider read using actual permitted account/locale; confirm non-synthetic source and timestamp.
A3 Fetch one permitted real Knowledge snapshot and Notion file via the gateway; validate fresh download hash and revocation state.
A4 Supply Vendor 1's actual brief to Vendor 2 with real frozen evidence; reach a complete, source-bound preview.
A5 Review that preview's factual claims and scope; edit it once and prove old approval cannot publish; re-approve exact revision.
A6 Send one STAGING_DRAFT to an allowlisted sandbox CMS; read back by provider ID, replay once and prove no duplicate draft.
A7 Interrupt/restart/cancel one job and one pending publication; verify finite retry, budget accounting, outbox and UNKNOWN reconciliation.
A8 Roll back the app release in staging, verify health and retained data/IDs, then restore live publication to OFF.

Artifacts: one integrated receipt pinning both module digests, contract digest, Knowledge policy/snapshot,
Notion receipt, CMS record ID, JUnit/probe log and preview snapshot. No public website/social writes.

If no real provider/CMS access exists, state BLOCKED_EXTERNAL and reuse already accepted isolated tests.
Do not quietly substitute another mock and label this integrated.
Failures are consolidated and routed to the responsible module; the unaffected vendor's whole suite is not manually re-audited.
After a fix, run changed boundary tests plus this small smoke set. Provider/framework/schema changes later need impact-based retesting.
