# THBISON — triển khai tích hợp nội bộ từ master source
Bạn tiếp nhận một monorepo với source Vendor1–6. Đây không phải app đã tích hợp hoàn chỉnh. Đọc AUDIT.md và provenance/INPUTS.json trước khi sửa. Mục tiêu: dựng Content OS trên VPS B ở staging, Knowledge gắn sau; không mở vòng trả vendor.

1. Verify integrity, tạo branch/worktree riêng trong repo người dùng đã cấp. Giữ bản baseline. Chạy scripts/check_core.py; lưu environment, command, exit code. Không rerun các suite không bị tác động chỉ để cộng PASS.
2. Chốt Node22/npm compatible với vendor và Python3.12. Reproduce clean install V1/V2; nếu lock mismatch trên toolchain chốt thì sửa lock tối thiểu (không upgrade hàng loạt), npm ci, typecheck, build trên DB TEST_ONLY mới. Không chạy build script bằng DATABASE_URL production kế thừa. Kiểm tra startup production SSR/API phù hợp TanStack/Nitro từ build output; không deploy vite dev làm server production.
3. Ghép hành vi qua adapter: V1 PlanningOutput.brief vào V2 draft ingress; V2 là UI chính, nối planning API thật thay synthetic planning nội bộ khi integration flag bật. Không copy đè route/package/migration của V1 vào V2. Persist brief ID/revision/project; giữ schema validation hai đầu. Giữ source domain functions đã pass.
4. V3 QueuePort→processor V2: durable job mapping, single retry owner, restart/reconcile, deadline/cancel; thay deferred mock queue qua flag. V5 CMS port DRY_RUN, approval authority/hash/policy bindings; không public effects. V4 Knowledge mock trả EvidenceBundle valid; tắt live Notion/V16. Hiển thị synthetic rõ.
5. V6 registry phải trỏ đúng clients/entrypoints vừa tích hợp; chạy actual local process E2E Planning→brief→synthetic evidence→article preview→approval mock→CMS dry-run. Identity/version/hash traces đúng nguồn, xác minh DB reload sau restart. Đọc INTERNAL_TAKEOVER vendor6; fake preflight không phải quyền mở live.
6. Phạm vi chốt gồm B01..B07 trong AUDIT. Tối đa 2 lượt patch→verify cho một blocker; nếu không xong ghi reproduction và HANDOFF_WITH_BLOCKERS, dừng việc đó. Không refactor/benchmark/feature creep. Owner projection cần proposal cụ thể và gate riêng, không đổi enum ngầm. Production/live gate không thể lấy offline PASS thay thế.
7. Khi local + clean build + persistent E2E đạt, dùng docs/VPS_B_RUNBOOK.md: inventory read-only VPS B, release directory mới, DB/volumes riêng, bind localhost, secrets ngoài repo, backup/rollback. Chỉ triển khai trong access và scope được user cấp ở phiên đó. Không VPS A/DB website, không mở cổng hay domain trước kiểm tra proxy/auth. Knowledge integration để phase sau.

Đầu ra một ZIP/repo commit hoàn chỉnh: integrated source, lockfiles, runnable deployment config, migrations, env.example, exact commands, JUnit/logs, release/source SHA, DEPLOYMENT_REPORT, rollback. Ghi từng gate PASS/FAIL/BLOCKED/NOT_RUN; mock/actual/live riêng. Không báo 'ổn định/production-ready' khi còn clean-build/E2E blocker. Nếu stage đã deploy, ghi URL/bind thực, backup và smoke results; không bịa địa chỉ VPS.
